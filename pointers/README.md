## 一句话总结

| 概念 | 一句话 | 前端对照 |
| --- | --- | --- |
| `&x` | 取 x 的地址（查门牌号） | 无对应（JS 碰不到地址） |
| `*p` | 按地址取值 / 改值（进房间） | 对象引用的"隐式"效果 |
| nil 指针 | 空门牌号，解引用直接 panic | `null`（JS 报错还能继续，Go 直接崩） |
| 指针传参 | 函数内 `*p = x` 能改外面变量 | JS 基本类型做不到，只能 return |
| 结构体传值 | **整块拷贝**，改的是副本 | JS 对象传引用（完全相反！） |
| 值接收者 | 方法里改不了原结构体 | JS class 方法 this.x 直接改实例 |
| 指针接收者 | 方法里能改原结构体 | ≈ JS class 方法 |
| `new(T)` | 返回 `*T`，值自动是零值 | —— |

## 面试速背（八股，复习时只看这一节）

- **& 和 ***：`&` 取地址，`*` 解引用（取值），互为逆运算
- **nil 指针**：零值，解引用直接 panic；判断"有没有"用 `p == nil`
- **传值 vs 传指针**：传值 = 拷贝，改不到外面；传指针能改外面
- **结构体**：默认整块拷贝；想改原结构体 → 传指针 / 指针接收者
- **值接收者 vs 指针接收者**：要改字段用指针接收者；只读用值接收者；结构体大用指针接收者（省拷贝）
- **什么时候用指针**：① 改外面 ② 大结构体省拷贝 ③ 可空（nil）④ 方法改字段
- **new vs make**：`new(T)` 返回指针（零值）；`make` 只用于 slice/map/channel
- **Go 没有指针运算**（不像 C），指针就是拿来传的，放心用

## 最容易踩的 3 个坑

1. **nil 指针解引用 panic**：`var p *int` 后直接 `*p` → 崩溃，先判断 `p == nil`
2. **结构体传值以为改了**：函数 / 值接收者里改了字段，外面没变（改的是拷贝）
3. **接收者选错**：要改字段却用值接收者 → "静默失败"（不报错但外面没变），选错接收者 = 埋 bug

## 补充：Day5 的 go mod（快速上手）

代码管理用 Go Modules，4 个命令够用：

```bash
go mod init 模块名        # 初始化模块（本仓库已经是 hello）
go get 包路径             # 装依赖，如 go get github.com/gin-gonic/gin
go mod tidy               # 整理依赖（自动加/删）
go run ./xxx              # 运行（本仓库每个文件夹是独立 main 包）
```

> 第 3 周上 Gin 框架时会大量用 go mod，现在眼熟即可
