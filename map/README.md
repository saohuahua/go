## 一句话总结

| 概念 | 一句话 | 前端对照 |
| --- | --- | --- |
| map 是什么 | key-value 字典，底层哈希表，平均 O(1) | `{}` / `new Map()` |
| 初始化 | 字面量 / `make`，**只声明是 nil map** | 空对象 `{}` 天生可用 |
| nil map 写入 | **直接 panic 崩溃**，必须先 make | ——（JS 没这坑） |
| 读不存在的 key | 返回零值，用 `v, ok := m[k]` 判断 | `undefined` |
| 删除 | `delete(m, key)` 内置函数 | `delete obj[key]` |
| 遍历 | **顺序随机**，想要有序先排序 key | JS Map 保插入序 |
| 引用类型 | 传参即改外部；`m2 := m` 不复制 | JS 对象传引用 |
| 复制 map | 必须手动 for 循环 | `{...obj}` / `structuredClone` |

## 面试速背（八股，复习时只看这一节）

- **底层结构**：`runtime.hmap` 哈希表 = 桶数组（`[]bmap`），每桶 8 个 key-value 槽位
- **查找流程**：`hash(key)` 算哈希值 → `哈希值 % 桶数量` 定位桶 → 桶内逐个比对 key → 平均 O(1)
- **冲突处理**：桶满（8 个槽全占）→ 挂溢出桶（overflow bucket）继续存
- **扩容触发**：溢出桶过多 → 桶数量翻倍 + 所有 key 重新算位置（rehash）→ 元素"搬家"
- **扩容与取地址的关系**：扩容 = 元素搬家 = 地址变了，所以 `&m[k]` 编译报错（第 2 节的坑）
- **nil map**：只读不崩（返回零值），**写入 panic**；判断存在用 `v, ok := m[k]`
- **不能取地址**：`&m[k]` 编译报错（rehash 时元素会搬家）
- **key 的限制**：必须可比较类型；slice / map / func 不能当 key
- **复制**：`m2 := m` 是共享不是复制，真复制要手动循环

## 最容易踩的 3 个坑

1. **nil map 写入 panic**：`var m map[string]int` 后直接 `m["x"] = 1` 崩溃，先 `make`
2. **读不到 key 当成有值**：返回值可能是合法零值（如 0），判断存在必须 `v, ok := m[k]`
3. **`m2 := m` 以为复制了**：两者指向同一个 map，改一个全变；真复制要手动循环
