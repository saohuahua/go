## 一句话总结

| 概念 | 一句话 | 前端对照 |
| --- | --- | --- |
| 切片 vs 数组 | 切片无长度、可动态增长 | JS 只有"切片"，没有定长数组 |
| 创建方式 | `[]int{...}` / `make` / 截取 | 数组字面量 |
| len / cap | 长度 / 容量（底层车位） | `length` |
| 截取 `s[a:b]` | **共享内存的视图，不是副本！** | 注意 ≠ JS 的 `slice()` |
| append | 容量满就扩容、换底层数组，必须接返回值 | `push` |
| copy | 真正的独立副本 | 深拷贝 |
| 传参 | 值传递，但共享底层数组 | 引用 vs 拷贝 |

## 面试速背（扩容机制）

- **触发时机**：`len == cap` 时，再 append 就会扩容
- **扩容步骤**：申请新数组 → 拷贝旧数据 → 切片指向新数组 → 旧数组回收
- **扩容倍率**：容量 < 256 直接翻倍；≥ 256 按约 1.25 倍增长（内存对齐会微调）
- **最大坑**：扩容换了底层数组后，旧的切片引用看不到新元素 → 必须 `s = append(s, x)`

## 最容易踩的 3 个坑

1. **截取共享内存**：`view := base[1:3]` 改了 `view`，`base` 也变 —— 想要副本用 `copy`
2. **append 忘记赋值**：`append(s, 4)` 不接返回值，扩容后数据就丢了
3. **函数里 append 外面看不到**：容量不足时换了底层数组，要 `s = append(s, ...)` 并返回
