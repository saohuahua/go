## 一句话总结

| 概念 | 一句话 | 前端对照 |
| --- | --- | --- |
| 接口 | 方法签名集合 = 能力契约，隐式实现 | TS 的 interface（不用写 implements） |
| 多态 | 一个接口变量装不同实现 | 父类引用指向子类对象 |
| 函数参数 | 函数只认契约，不认具体类型 | 依赖注入 |
| 字段注入 | 依赖从外面塞进来，随时能换 | 构造函数传参 / DI 容器 |
| 换实现 | 生产 MySQL、测试 mock，业务代码不动 | 换 adapter |
| any | 空接口 = 能装任何类型 | TS 的 unknown |
| 类型断言 | `v, ok := x.(T)` 掏出具体类型 | `as` / instanceof |
| type switch | `switch v := x.(type)` 分拣类型 | typeof + 收窄 |

## 面试速背（八股，复习时只看这一节）

- **隐式实现**：方法签名对上就自动实现，不用 implements（对比 TS 显式声明）
- **接口变量能调的方法 = 接口声明的方法**（不是实现者的全部方法）
- **值接收者实现 → 值和指针都满足**；**指针接收者实现 → 只有指针满足**（编译报错）
- **接口值 = (类型, 值) 对**：装了 nil 指针的接口 ≠ nil 接口，别直接 `s == nil`
- **空接口 any**：能装任何类型；取出来用必须断言（`v, ok := x.(T)`）
- **断言两种写法**：单返回值类型不对会 panic；comma-ok 安全，永远用 comma-ok
- **铁律**：接收接口，返回结构体；接口要小（1~2 个方法）；别提前造接口
- **什么时候用接口**：有多个实现要换 / 要写 mock 测试 / 写库；只有一个实现别硬造

## 最容易踩的 4 个坑

1. **断言忘了 comma-ok**：`x.(string)` 类型不对直接 panic 崩掉整个服务
2. **指针接收者实现接口，却传值**：编译报错，一脸懵（用值接收者实现就两边都兼容）
3. **判断接口空不空用 `s == nil`**：装了 nil 指针的接口不是 nil，要先断言
4. **JSON 数字反序列化后是 float64**：`.(int)` 断言失败，先断 float64 再转
